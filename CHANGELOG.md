(`v<version> - ...`) mark the points where `VERSION` was bumped.

- v0.1.679 - sync weight: exclude the backups bookkeeping table from snapshots (it carried thousands of replicated watermark rows on every pull, and because it was synced those rows multiplied across the mesh) and drop the snapshot's indexes before the copy; the merge reads the table once in rowid batches, so indexes were only megabytes of B-tree pages.
- v0.1.678 - sync: a peer with no watermark pulls the last 24 hours instead of every table in full; a slow tablet's cold pull held the single export lock for minutes (appointments and continent are ~110k rows each) and starved every other peer, so bound it. The nightly three-day reconciliation and a manual gimme still reach further.
- v0.1.677 - sync: a merge read only one row per table because the snapshot cursor was finished by the first row's app-database work, so peer-only appointments never arrived; read the snapshot in bounded rowid batches (and log read/inserted counts and refused inserts). A synced settings row no longer replays its local side effects (websocket reload, BLE toggle push, task re-registration, name-change broadcast that opened the app window), which is what hung every merge in settings. A completed pull is recorded as `remote_upgraded` rather than `remote_update`, so the peer's watermark finally advances and a pull stops re-exporting the whole database; gimme/deep windows leave the watermark alone.
- v0.1.676 - sync: stop the remote export at the 2000-row progress tick; `database_grabber`'s abandoned-statement sweep finished the still-open export cursor on every progress update, so every table was capped at 2000 rows and a cold peer never finished pulling.
- v0.1.675 - sync: a remote export with no prior watermark or gimme now reads the whole table (default 0, not `rightNow`), so a cold peer pulls Home/Weather and every appointment it has never seen instead of only the last 20 seconds.
- v0.1.674 - the api APK is a release product: `app_build` builds and bumps both repos, `app_publish` uploads `app_release.json` and `api_release.json` beside both APKs, and `app_release_sync` pulls each from GitHub; the T-Deck display runs at 40 MHz again (TFT_eSPI `SUPPORT_TRANSACTIONS` was off, so `SD.begin` left the shared bus at 800 kHz), renders LVGL in partial mode, budgets GPS reads, and drops unused PNGdec and widgets.
- v0.1.673 - sync: pull by the last-confirmed watermark again, not per-table delta cuts; the plan could record a peer as fully seen after excluding rows below its own newest stamp, so appointment changes stopped arriving over `remote_upgrade`.
- v0.1.672 - appointments: an open session is running however long it has run; NFC start/record tags no longer toggle into a stop, and a place's long session keeps navigation from starting a fresh one.
- v0.1.671 - embedded reply audio: `https_download` wrote binary through `appendFile`'s `file.print`, so every WAV was truncated at the first NUL and the T-Deck stayed text-only; both devices now write the exact byte count, open the file once, and bound a fetch to 15 s, and the T-Deck's fetch worker is created once at boot (fragmentation could not start a fresh 12 KB task per reply).
- v0.1.670 - nfc: judge a stale open session by the app's configured length even on a handheld with no duration row of its own.
- v0.1.668 - nfc: a start tag is not turned into a stop by a stale synced open row, the stop names the session the header shows, and the tap runs on the reading machine only rather than on every peer.
- v0.1.667 - sync: never carry window/tab state between machines (Libro Chequing opening everywhere), and let a signed peer pull-now through a lapsed session so a stuck tablet can catch up.
- v0.1.667 - embedded voice: the T-Deck fetches a spoken reply inline (its 12 KB fetch task could not start, so answers stayed text-only), a wake word holds the watch screen through the capture even on a 5 s tilt glance, and both devices chime when a wake capture ends with no command to ship.
- v0.1.666 - records repair rail: an orphan the accurate copy does not hold is tombstoned by the peer that has it, instead of inventing an end.
- v0.1.665 - records: a peer-verified quiet repair route so a machine holding the accurate session closes another peer's stale open row (no session, no view fan-out).
- v0.1.664 - a Now Me that names a different House machine drops the old wss socket first. The t-deck kept its control channel on the previous machine because `tauth_connect` is a no-op while `ws_connected` is 1; every path that applies a new Now Me (HTTP, BLE, saved profile) now closes it and redials the address just delivered.
- v0.1.663 - Now Me hands the rotated pairing row to the LAN peers inside the request (`operator_door_push`, two seconds for two machines) instead of a forked relay that did not reliably reach them; the peer route verifies the signed request, so no session cookie is involved. A device that falls back now authenticates on its first probe.
- v0.1.662 - the headless relay builds a real form body. `Mojo::Message::body_params` is a getter in this Mojolicious, so `relay_headless`'s POST always carried an empty body and a peer never received the relayed request (the Now Me pairing push among them). The parameters are now form-encoded into the request body.
- v0.1.661 - the pairing push stamps the row in milliseconds. now_me's own clock is in seconds, so the relayed copy sorted below the row it replaced and the fallback House kept the previous pair; the local row and every peer copy now share one millisecond server_time.
- v0.1.660 - the Now Me pairing row reaches the other House machines immediately: a dedicated peer-verified `/manager/operator_door` route accepts the signed push (the generic setting route sits behind the Gate, so the relay was silently landing on the denial page). With the pair stored on every reachable machine, a device that falls back authenticates on its first probe instead of waiting for a settings sync.
- v0.1.659 - House failover without starving the devices: the t-deck's mbedTLS allocator now sends small crypto allocations (the BIGNUM limbs) to PSRAM as well as the large handshake buffers, and ordinary allocations of 64 bytes or more prefer PSRAM, so the wake-word front-end, BLE and LVGL can coexist with TLS (internal heap went from ~10 KB to ~34 KB and wss/HTTPS work again); the TDM read buffers live in PSRAM, and the failover worker is created only while a failure or a fallback is pending, returning its stack once the preferred machine answers. Now Me pushes the rotated operator_door row to every peer over the signed relay immediately, so a device that falls back can authenticate at once; the durable digest remains the backstop.
- v0.1.658 - sync: pull and merge in forked workers so they cannot starve the prefork heartbeat; copy the remote export in one transaction, bound peer timeouts, and release/clear the pull marker by pid.
- v0.1.657 - the House failover probe checks what a peer actually answered, not just the HTTP status: `/watch/time` returns the denial template with 200 (the same content type as the timestamp, ~130 KB), so a live machine that refused the pair is no longer mistaken for a fallback and the device moves on. The `operator_door` row is part of the durable settings digest, so a rotated Now Me pair reaches the other House machines on the next sync instead of waiting for an unrelated change.
- v0.1.656 - web measures select a value by JSON path, table row or label instead of a page-wide count; the picker tests each shape against the page before offering it, a label may be bare text in a container, and one number parser keeps signs and precision; `scripts/web_measures_audit.pl` checks or converts every app and prunes dead measure rows.
- v0.1.655 - every embedded device now finds a live House machine when its stored homebase goes away. Each computer/mobile/server advertises `_jawnos-house._tcp` (purpose and the arm/coms/bestow ports it dials), and Now Me carries the LAN's House list to the watch, t-deck and Pico; when the preferred machine stops answering, the device probes the others with its own Now Me pair and moves its HTTP and wss addresses to the first that answers, returning to the preferred machine as soon as it is back. The serving side reads the device's `operator_door` by device (newest row) rather than by its own device class, so a phone can serve a watch paired to a laptop and a laptop can serve a deck paired to a phone. Firmware rebuilt for watch, t-deck and alarmclock.
- v0.1.654 - Bluetooth mesh: a configurable link cap, JawnOS scan identity, and chip-to-chip relay.
- v0.1.653 - watch/deck WiFi reply probe uses the devices' own web server port (3000, the mDNS-advertised one) rather than 80, so a WiFi-connected device is recognized and pulls the reply instead of being sent the BLE stream.
- v0.1.652 - a settings audit compares the live table with any sealed snapshot, showing every value that changed (with both write times and a backdated flag) and restoring a selected subset with a current server_time; a 401 is treated as a lapsed session rather than a request fault, so the phone's background sync no longer paints a red dot, and a phone waking after a long sleep reloads once to pick up a fresh ticket.

- v0.1.650 - audio replies prefer WiFi too: the server renders the spoken answer once as a WAV and sends a small say_audio_ready over BLE; a WiFi-connected watch or t-deck pulls it from the serving House machine (so a fallback machine works, not just the stored homebase), plays it, and deletes the one-shot file. An off-WiFi device gets the existing streamed BLE PCM parts immediately. The t-deck's voice upload also gains the WiFi-first path, falling back to BLE at once when WiFi is down.
- v0.1.649 - a successful pull records the peer's per-table picture, so a table that diverges because the peer is simply behind us is full-read once and then skipped until that peer's rows actually change; a changed picture still gets the full read that catches an offline row.
